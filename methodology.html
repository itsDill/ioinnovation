Methodology

How this filing dataset is built

Data as of: 2026-08-18. Source: SEC EDGAR submissions and filing archive documents.

Pipeline summary

  • Filer CIK list and issuer CIK list are maintained in static JSON config files.
  • Daily scheduled GitHub Actions run fetches SEC submissions JSON and filing indexes.
  • 13F info table XML is parsed into issuer, class, CUSIP, value, and share fields.
  • Recent Form 4 filings are extracted from issuer submissions indexes.

Normalization rules

  • Value fields are interpreted as dollars as reported in source payloads.
  • Ticker mapping uses deterministic issuer-name and class-based matching.
  • BTC-linked tags are rule-based from ticker and issuer-name patterns.
  • Rows are sorted by reported value and include derived position weight per filer.

Known gaps and caveats

  • 13F is delayed and may not reflect current holdings.
  • Some issuers and share classes cannot be mapped confidently to a ticker.
  • Form 4 includes non-open-market transactions that can be misread as conviction trades.
  • Corporate actions and identifier changes can cause temporary mismatches.

Verification and corrections

Every filer page links to the source SEC filing. If you identify a mismatch, email contact@ioinnovationfund.com with the page URL and EDGAR source link.
